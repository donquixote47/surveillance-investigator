# Project context: Trade Surveillance Alert Investigator on AgentCore

## What this is

George's TFC AI/ML project (Agentic AI learning path), presented to a mentor. A Level-1 trade-surveillance analyst agent that investigates spoofing/layering alerts raised by a deterministic detector, gathers evidence through governed tools, writes an auditable investigation report, and **proposes** a disposition. A human records the disposition; the agent never can.

Two goals with equal weight: (1) solve a real problem for brokers and trading firms (George's AWS customers), (2) learn Amazon Bedrock AgentCore in depth. When they conflict, prefer the option that teaches more AgentCore, as long as the domain story stays honest.

George is a TAM at AWS whose customers are brokers, traders and some HFT firms. He is not a surveillance or compliance expert and is learning the domain through this project. Explain domain concepts when they come up; don't assume.

## Hard constraints

- Region: eu-west-2 (London) only. All AgentCore control-plane services and the `eu.` Claude inference profiles verified there on 2026-11-02. Note the `eu.` profiles route inference across seven EU regions, not London alone.
- Zero cost to third-party services. No paid data or APIs. Synthetic market data only, generated by our own simulator (ABIDES optional later).
- AWS cost is not a constraint (George, 2026-11-02): do not cut data or scope to save dollars. Still announce the cost before creating billable resources, stop Runtime and Code Interpreter sessions when done, and record every resource in `STATUS.md`. The deploy-guard hook asks for confirmation on deploy/create commands.
- **Every AWS resource we create carries the tags `Project=agentcore-surveillance-investigator` and `auto-remove=no`.** The account has an automatic cleaner; a resource without `auto-remove=no` can be deleted under us. Enforcement: `Tags.of(app).add(...)` in `infra/app.py` (covers everything in the CDK stack); `Tags.of(this).add(...)` in the AgentCore CLI's generated `agentcore/cdk/lib/cdk-stack.ts`; `scripts/tag_agentcore.py` after every `agentcore deploy` tags Runtime, Gateway, Memory, Policy Engine, Code Interpreter and evaluators by API as a second layer; `scripts/check_tags.py` lists any project resource missing the tag. Resources created ad hoc with the AWS CLI or the console get the tags in the same command, or they are not created.
- Synthetic data only. Never real customer order data, trader names, or anything from George's AWS customers. Customers are used only for problem validation conversations, not data.
- Never commit secrets; `.env` is gitignored.
- The agent proposes, a human disposes. This is enforced by AgentCore Policy at the Gateway, not by the prompt. Any design that weakens this needs an explicit decision-log entry.

## Stack and conventions

- Python 3.14 pinned with `uv` (system Python 3.14.2; all SDKs install and import on it as of 2026-11-02; Lambda `python3.14` and AgentCore Runtime `PYTHON_3_14` both exist). `uv run`, `ruff` for lint/format, type hints everywhere.
- Agent framework: Strands Agents. Models (Bedrock, `eu.` inference profiles): Haiku 5.5 for development loops; Sonnet 5.5 as the default agent for demos and evaluation runs; Opus 5.5 as the Phase 5 model-comparison arm and as the rationale-rubric judge. Opus becomes the default only if the comparison run justifies it (decision log 2026-11-02).
- AgentCore resources (Runtime, Gateway, targets, Policy Engine, policies, Memory, evaluators, config bundles) via the `agentcore` CLI 1.0.1 (`npm i -g @aws/agentcore`) and `agentcore/agentcore.json`. The Python starter toolkit is not installed and not needed.
- Mock surveillance back end ("the firm"): AWS CDK in Python under `infra/`, its own stack. Lambda tools + DynamoDB + S3 + Cognito user pool + human-path Lambdas. Deploy order: `infra/` first (outputs Lambda ARNs, Cognito discovery URL), then `agentcore deploy`. No Terraform.
- Model ids: `eu.anthropic.claude-haiku-5-5`, `eu.anthropic.claude-sonnet-5-5`, `eu.anthropic.claude-opus-5-5` (inference-profile ids; bare model ids are not on-demand in eu-west-2).
- Gateway target name is `surv`; tools are therefore `surv___<tool>` in MCP and `AgentCore::Action::"surv___<tool>"` in policies.
- AgentCore resource names use the prefix `surv_investigator` (Runtime, Memory, Policy Engine) or `surv-investigator` (Gateway). Tag everything `Project=agentcore-surveillance-investigator`.
- Policies live in `policies/` as `.cedar` files, one rule per file, named `NN-<what-it-enforces>.cedar`, each with a header comment stating the business control it implements.
- Synthetic data generator and detector live in `src/market_sim/` and `src/detector/`; agent in `src/agent/`; tool Lambdas in `src/tools/`.
