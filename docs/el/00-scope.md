# 00 - Εύρος

## Μία πρόταση

Ένας AI agent στο Amazon Bedrock AgentCore που διερευνά alerts (ειδοποιήσεις) για spoofing (τοποθέτηση εντολών με σκοπό την ακύρωση, για να δημιουργηθεί ψευδής εικόνα ζήτησης ή προσφοράς) και layering (spoofing με πολλές εντολές σε διαδοχικά επίπεδα τιμής) που παράγει ένας detector (μηχανισμός ανίχνευσης) trade surveillance (εποπτείας συναλλαγών), συγκεντρώνει τα στοιχεία που θα συγκέντρωνε ένας αναλυτής Level 1, συντάσσει μια ελέγξιμη έκθεση διερεύνησης και προτείνει μια disposition (τελική απόφαση επί του alert), την οποία στη συνέχεια καταγράφει ένας άνθρωπος.

## Γιατί αυτό και όχι η ιδέα με τις κυρώσεις

Το έργο ξεκίνησε ως εργαλείο διερεύνησης alerts από sanctions screening (έλεγχο κυρώσεων) σε διασυνοριακές πληρωμές. Κρατήσαμε το σχήμα της ιδέας και αλλάξαμε το πεδίο. Οι λόγοι, κατά σειρά βαρύτητας:

1. **Είναι το πρόβλημα των πελατών του Γιώργου.** Οι πελάτες του στο AWS είναι brokers (χρηματιστηριακές εταιρείες), trading firms και ορισμένες εταιρείες HFT (high-frequency trading, συναλλαγές υψηλής συχνότητας). Όλοι ανεξαιρέτως έχουν υποχρέωση surveillance (εποπτείας) για κατάχρηση αγοράς (EU MAR, ο Κανονισμός για την κατάχρηση της αγοράς, Άρθρο 16(2)· MiFID II Άρθρο 17 / RTS 6 για όσους κάνουν αλγοριθμικές συναλλαγές· FINRA 3110 στις ΗΠΑ). Λίγοι από αυτούς διαχειρίζονται μεγάλες ροές πληρωμών, οπότε το sanctions screening είναι μικρό κομμάτι της δουλειάς τους στο compliance (κανονιστική συμμόρφωση). Βλ. `01-domain-primer.md`.
2. **Ίδιο μοτίβο, άρα δεν χάνεται τίποτα από όσα μάθαμε.** Ένας ντετερμινιστικός detector παράγει alerts· τα περισσότερα είναι false positives (ψευδώς θετικά)· ένας άνθρωπος διερευνά το καθένα· ο regulator (εποπτική αρχή) θέλει τον συλλογισμό γραμμένο. Η αρχιτεκτονική στο AgentCore είναι πανομοιότυπη. Αλλάζουν μόνο τα tools και τα δεδομένα.
3. **Τα συνθετικά δεδομένα είναι πιο πειστικά εδώ.** Το spoofing ζει αποκλειστικά σε γεγονότα εντολών και συναλλαγών, που ένας simulator (προσομοιωτής αγοράς) μπορεί να παραγάγει μαζί με ground truth (γνωστές σωστές ετικέτες). Η διερεύνηση κυρώσεων στηρίζεται σε δεδομένα ταυτότητας (ημερομηνίες γέννησης, διευθύνσεις, μητρώα) που είναι δύσκολο να πλαστογραφηθούν πειστικά.
4. **Ο agent έχει περισσότερα πάνω στα οποία να συλλογιστεί.** Για να κρίνει κανείς αν ένα μοτίβο από cancels (ακυρώσεις εντολών) είναι market making (παροχή ρευστότητας με συνεχείς τιμές αγοράς και πώλησης), αλγοριθμική ανατιμολόγηση, περικοπή λόγω ορίου κινδύνου ή χειραγώγηση, χρειάζεται συλλογή στοιχείων σε πολλά βήματα και γραπτή επιχειρηματολογία. Αυτό ακριβώς προσθέτει ένας agent γενικού σκοπού σε σχέση με έναν classifier.
5. **Η ανταγωνιστική θέση είναι παρόμοια, άρα ούτε εκεί χάνουμε κάτι.** Και οι δύο αγορές έχουν εδραιωμένους παίκτες (κυρώσεις: Silent Eight, WorkFusion· surveillance: NICE Actimize, Nasdaq, Eventus). Και στις δύο, η διερεύνηση alerts με agents είναι το νεότερο στρώμα, και οι μικρές και μεσαίες εταιρείες εξυπηρετούνται ανεπαρκώς.

Η εκδοχή για τις κυρώσεις έχει αρχειοθετηθεί στο `shared/tam-work/archive/agentcore-sanctions-triage-2026-09/` για αναφορά. Στην παρουσίαση αναφέρεται σε μία γραμμή, ως δεύτερο plug-in πάνω στον ίδιο πυρήνα.

## Εντός εύρους

| Διάσταση | Απόφαση |
|---|---|
| Τύπος κατάχρησης | Μόνο spoofing και layering. Ένας detector, μία οικογένεια σεναρίων, διερευνημένη σε βάθος. |
| Κατηγορία περιουσιακών στοιχείων | Μετοχές (cash equities). |
| Τόπος διαπραγμάτευσης | Ένα lit order book (βιβλίο εντολών με ορατές τιμές, ένα και μόνο προσομοιωμένο χρηματιστήριο). Χωρίς ανάλυση μεταξύ τόπων διαπραγμάτευσης ή μεταξύ κατηγοριών περιουσιακών στοιχείων. |
| Συμμετέχοντες | Οι traders (διαπραγματευτές) και οι αλγόριθμοι της ίδιας της εταιρείας, μαζί με τη ροή εντολών των πελατών της, όπως θα την έβλεπε ένας broker. |
| Είσοδος | Ένα alert τη φορά, από έναν ντετερμινιστικό detector που γράφουμε εμείς, μαζί με τα ακατέργαστα γεγονότα εντολών και συναλλαγών γύρω από αυτό. |
| Ρόλος του agent | Αναλυτής Level 1: συλλέγει στοιχεία, υπολογίζει διακριτικούς δείκτες, συντάσσει την έκθεση διερεύνησης, προτείνει μία από τρεις dispositions (κλείσιμο ως false positive, κλιμάκωση σε Level 2, σύνταξη προσχεδίου STOR, δηλαδή Suspicious Transaction and Order Report, της αναφοράς ύποπτων συναλλαγών και εντολών προς την εποπτική αρχή). |
| Ρόλος του ανθρώπου | Καταγράφει τη disposition. Μπορεί να την ανατρέψει, να προσθέσει σχόλια και να στείλει feedback που ο agent θυμάται. |
| Δεδομένα | Μόνο συνθετικά, παραγόμενα από τον δικό μας simulator limit order book, με εμφυτευμένα σενάρια και ετικέτες ground truth. |
| Αξιολόγηση | Dataset (σύνολο δεδομένων) με ετικέτες· κύρια μετρική είναι το ποσοστό των false-positive alerts που ο agent προτείνει να κλείσουν, μετρούμενο μόνο με recall (ανάκληση: το ποσοστό των πραγματικών περιπτώσεων που δεν χάνονται) 100% στις πραγματικές περιπτώσεις κατάχρησης. |
| AgentCore | Runtime, Gateway (Lambda tools ως MCP), Identity (Cognito, ομάδες L1 και L2), Policy (ντετερμινιστικά guardrails, περιλαμβανομένων χρονικών κανόνων), Memory (αποφάσεις και feedback αναλυτών), Code Interpreter (ad-hoc ανάλυση και γραφήματα για την έκθεση), Observability (audit trail, δηλαδή ίχνος ελέγχου), Evaluations (evaluators με ground truth και custom), Optimization (προτάσεις για το prompt, configuration bundles, A/B μέσω του Gateway, με προώθηση μόνο μέσα από το ντετερμινιστικό gate). |
| Παραδοτέο | Λειτουργικό demo, δίγλωσση τεκμηρίωση, παρουσίαση στον mentor με σενάριο demo. |

## Εκτός εύρους

- Ανίχνευση σε πραγματικό χρόνο. Ο detector τρέχει πάνω σε ολοκληρωμένα χρονικά παράθυρα· ο agent δουλεύει μια ουρά.
- Κατασκευή ανταγωνιστικής μηχανής ανίχνευσης. Ο detector μας είναι επίτηδες απλός και θορυβώδης, για να μιμείται την ποιότητα alerts για την οποία παραπονιούνται οι εταιρείες.
- Άλλοι τύποι κατάχρησης (wash trades, insider dealing, marking the close, front running, momentum ignition, quote stuffing). Αναφέρονται στο primer για να γνωρίζει ο Γιώργος το τοπίο· δεν υλοποιούνται.
- Surveillance επικοινωνιών (chat, φωνή, email).
- Αυτόνομη disposition. Ο agent δεν μπορεί να καλέσει το tool που καταγράφει μια disposition· το AgentCore Policy το απαγορεύει στο Gateway. Πρόκειται για αρχή σχεδιασμού, όχι για περιορισμό της φάσης 1.
- Ανάλυση σε πολλές κατηγορίες περιουσιακών στοιχείων ή σε πολλούς τόπους διαπραγμάτευσης.
- Θωράκιση για παραγωγή (multi-region, DR, SLAs), δεδομένα πελατών, ή οτιδήποτε από τους πραγματικούς πελάτες του Γιώργου.
- Υποβολή STOR σε regulator. Ο agent συντάσσει προσχέδιο των αφηγηματικών πεδίων ενός STOR· τίποτα δεν υποβάλλεται πουθενά.

## Επεκτάσεις (μόνο αν ο πυρήνας έχει ολοκληρωθεί και αξιολογηθεί)

- Αντικατάσταση ή συμπλήρωση του simulator μας με το ABIDES (τον open-source agent-based προσομοιωτή αγοράς της J.P. Morgan) για πιο ρεαλιστική ροή υποβάθρου.
- Ένας agent-ελεγκτής Level 2 που λαμβάνει κλιμακώσεις μέσω A2A και αμφισβητεί την έκθεση του L1.
- Online αξιολόγηση σε ζωντανή κίνηση και δεύτερη επανάληψη Optimization.
- Ένα λεπτό plug-in για κυρώσεις που επαναχρησιμοποιεί τον ίδιο πυρήνα, για να δείξουμε ότι η αρχιτεκτονική γενικεύεται.

## Κριτήρια επιτυχίας για την παρουσίαση TFC

1. Ένας mentor που δεν έχει δει ποτέ trade surveillance καταλαβαίνει το πρόβλημα σε πέντε λεπτά από τα έγγραφα και το demo.
2. Το demo δείχνει μία πραγματική περίπτωση spoofing και δύο ή τρία σενάρια false positive διερευνημένα από την αρχή ως το τέλος, με την έκθεση, την προτεινόμενη disposition και τα στοιχεία.
3. Το demo δείχνει το Gateway να αρνείται στον agent μια ενέργεια (καταγραφή disposition, ή πρόταση κλεισίματος πριν συλλεχθούν στοιχεία), με την άρνηση ορατή στα logs του Policy.
4. Ο πίνακας αξιολόγησης δείχνει τη μετρική σε ολόκληρο το dataset με ετικέτες, με τον αριθμό των πραγματικών περιπτώσεων που χάθηκαν στο μηδέν.
5. Κάθε υπηρεσία AgentCore στη γραμμή «εντός εύρους» χρησιμοποιείται για έναν λόγο που ο Γιώργος μπορεί να εξηγήσει σε δύο προτάσεις.
