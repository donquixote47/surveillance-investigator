# 09 - Αποφάσεις προϊόντος: τι υλοποιήθηκε, γιατί, και πώς πωλείται

Το αρχείο κάθε απόφασης επιπέδου προϊόντος σε αυτό το έργο, με τον λόγο και τα τεκμήρια, γραμμένο ώστε ένας solutions person να μπορεί να εξηγήσει το προϊόν σε αγοραστή και ένας μέντορας να δει πού το Amazon Bedrock AgentCore κάνει τη δουλειά. Ο detector και ο simulator μένουν επίτηδες στο φόντο: είναι ο πάγκος δοκιμών, όχι το προϊόν. Κάθε απόφαση συνδέεται με τη χρονολογημένη καταχώριση στο `decision-log.md` όπου ζυγίστηκαν οι εναλλακτικές· οι μετρημένοι αριθμοί προέρχονται από το `04-synthetic-data-and-evaluation.md`, ενότητα 4.6. Κατάσταση στις 2026-11-07, Runtime v12.

## 1. Το προϊόν σε τρεις προτάσεις

Ένας ελεγχόμενος investigator Level 1 για alerts εποπτείας συναλλαγών. Τοποθετείται μετά από οποιονδήποτε detector και πριν από τον αναλυτή, συγκεντρώνει τα τεκμήρια μέσω ελεγχόμενων tools, εφαρμόζει τα γραπτά πρότυπα της ίδιας της εταιρείας, γράφει την αναφορά που θα διαβάσει ο ρυθμιστής, και προτείνει διάθεση που καταγράφει άνθρωπος. Τρέχει στον λογαριασμό AWS της εταιρείας πάνω στο Amazon Bedrock AgentCore, που παρέχει τους ελέγχους που χρειάζεται μια λειτουργία compliance πριν αφήσει έναν AI agent κοντά σε υπόθεση εποπτείας: ένα μοναδικό σημείο ελέγχου για κάθε ενέργεια, ντετερμινιστικούς κανόνες που το μοντέλο δεν μπορεί να παρακάμψει με λόγια, την ταυτότητα του ανθρώπου πίσω από κάθε κλήση, πλήρες ίχνος, και μετρημένο, εκδοχοποιημένο μονοπάτι αλλαγής.

## 4. Πού το AgentCore κάνει τη δουλειά

Αυτό είναι το μέρος που πρέπει να ζυγίσει ένας μέντορας. Κάθε υπηρεσία απαντά σε συγκεκριμένη αντίρρηση που εγείρει μια λειτουργία compliance, και καθεμία ασκήθηκε στην αξιολόγηση, όχι μόνο δηλώθηκε.

| Υπηρεσία AgentCore | Τι κάνει στο προϊόν | Η αντίρρηση που απαντά | Τι μάθαμε χρησιμοποιώντας την |
|---|---|---|---|
| **Runtime** | Φιλοξενεί τον investigator ως HTTP agent· ένα απομονωμένο session ανά alert· το JWT του αναλυτή είναι ο εισερχόμενος authorizer και προωθείται στα tools· configuration bundles διαβάζονται ανά αίτημα από την κεφαλίδα W3C `baggage`. Εκδόσεις 1-12 σε πέντε ημέρες· ένα endpoint `demo` θα καρφωθεί στο v12. | «Πού τρέχει αυτό και ποιος μπορεί να το καλέσει;» | Η απευθείας εγκατάσταση κώδικα Python 3.14 δουλεύει· το bundle επιλύει mcp 1.x ενώ ο σταθμός εργασίας έχει 2.x, οπότε ο κώδικας transport πρέπει να είναι ανεξάρτητος έκδοσης (το v11 απέτυχε σε import, το v12 το διόρθωσε). |
| **Gateway** | Μετατρέπει μία Lambda με δώδεκα tools σε MCP tools υπό τον στόχο `surv`· εισερχόμενο JWT από τον πάροχο ταυτότητας της εταιρείας· όρια ρυθμού ανά αναλυτή (60 κλήσεις/λεπτό, 3 προτάσεις/λεπτό)· το Policy Engine συνδεδεμένο· vended logs με κάθε κλήση και κάθε απόφαση κανόνα. | «Πώς βλέπουμε και ελέγχουμε κάθε ενέργεια του agent;» | Ένα 429 από το όριο ρυθμού σκοτώνει τη σύνδεση MCP αν ο client δεν επαναλάβει· ο ενσωματωμένος κανόνας του Gateway διαβάζει και configuration bundles και χρειάζεται την άδεια IAM. |
| **Policy** | Εννέα δηλώσεις Cedar και χρονικές σε ENFORCE: κλειστή λίστα επιτρεπόμενων, τεκμήρια πριν την πρόταση, ιστορικό πριν το κλείσιμο, μία πρόταση ανά alert, σύνταξη STOR μετά από πρόταση DRAFT_STOR και μόνο για L2, όριο στις αντλήσεις γεγονότων. Οι αρνήσεις ονομάζουν τον κανόνα. | «Ο agent θα μπορούσε να συμπεράνει χωρίς να κοιτάξει, ή να κλείσει μόνος του.» | Το `LOG_ONLY` δεν καταγράφει γεγονότα response, οπότε οι χρονικοί κανόνες δοκιμάζονται μόνο σε ENFORCE· μια policy χωρά τρεις χρονικούς τελεστές· ο ρόλος του Gateway χρειάζεται `GetWorkloadAccessToken`. |
| **Identity** | Cognito user pool με ομάδες L1 και L2 ως εισερχόμενος πάροχος JWT· ο agent τρέχει υπό την ταυτότητα του αναλυτή· η workload identity του Gateway για το μονοπάτι των tools. | «Ποιος επιτρέπεται να το χρησιμοποιεί, και ποιος έκανε τι;» | Στείλτε το access token, όχι το id token (το `allowedClients` διαβάζει `client_id`)· το claim των ομάδων φτάνει ως string tag. |
| **Memory** | Ένας πόρος, στρατηγική SEMANTIC· άμεσες εγγραφές ανά διάθεση και feedback διανεμημένες σε namespaces trader και desk, πλέον εξαγωγή από ελεύθερο feedback· ανάκληση ως tool του Gateway ώστε να είναι υπό Policy και στο log. | «Θα μάθει το λάθος μάθημα από έναν αναλυτή.» | Μετρήθηκε: +0,7 μονάδες safe close, override 6,6% έναντι 7,8% χωρίς· ο spoofer με καθαρό ιστορικό πιάστηκε με και χωρίς. Ο agent χαρακτηρίζει τη μνήμη «μόνο πλαίσιο». |
| **Observability** | Ίχνη OTel κάθε βήματος στο CloudWatch, Transaction Search ενεργό, logs του Gateway με αποφάσεις policy, το UI του αναλυτή που συνδέει κάθε υπόθεση με το ίχνος της. | «Πώς θα το έλεγχε ένας ρυθμιστής;» | Τα spans φέρουν τις πλήρεις εξόδους των tools, που είναι αυτό που κάνει δυνατό τον έλεγχο πιστότητας. |
| **Evaluations** | Ενσωματωμένοι evaluators Correctness, GoalSuccessRate και Trajectory έναντι ground truth που παράγεται από τις ετικέτες· custom rubric αιτιολόγησης με κριτή Opus 5.5· βαθμολόγηση στα sessions που ήδη έτρεξε το harness. | «Πώς ξέρουμε ότι είναι καλό, και ακόμη καλό μετά από αλλαγή;» | Τα ονόματα tools του ground truth φέρουν το πρόθεμα του Gateway· ο κριτής διαβάζει την αναφορά, όχι την ετικέτα, και οι χαμηλότερες βαθμολογίες του έδειξαν πραγματικά κενά συλλογισμού. |
| **Optimization** | Μια recommendation συστημικού prompt έναντι του rubric από 167 πραγματικά sessions· δύο configuration bundles (έλεγχος, recommendation) πλέον ένα τρίτο για το arm μοντέλου· η recommendation αναπαράχθηκε offline μέσω του harness. | «Θα βελτιωθεί, ή απλώς θα παρεκκλίνει;» | Η recommendation εισήγαγε πύλη έγκρισης που η εξήγησή της ισχυρίστηκε ότι «διατήρησε» και βελτιστοποίησε προς τον κριτή, όχι τη μετρική της εταιρείας· η offline πύλη την απέρριψε. Οι recommendations είναι υποψήφιοι. |
| Code Interpreter | Σχεδιασμένο για ad-hoc γραφήματα στην αναφορά. **Δεν υλοποιήθηκε**· οι ντετερμινιστικές μετρικές έμειναν στη Lambda και κανένα βήμα demo δεν το χρειάστηκε. | | Πείτε το όταν ρωτηθείτε. |

Decision log: 2026-11-03 «Gateway declared in `agentcore.json`», «Rate limits as a brake», «Report validation in the agent»· 2026-11-04 «Policy Engine enforced from day one», «Policy 02 as a closed allow-list»· 2026-11-05 «Memory: direct records plus extraction»· 2026-11-05 «Evaluation harness»· 2026-11-06 καταχώριση recommendation.

## 5. Τι παίρνει ο πελάτης

- **Τον investigator**: κώδικα agent, Lambdas tools, το API ανθρώπινου μονοπατιού, το UI αναλυτή (Streamlit, UI αναφοράς· μια εταιρεία θα ενσωμάτωνε τις κλήσεις στο δικό της εργαλείο υποθέσεων), το σύνολο policies, το σχήμα μνήμης, υποδομή ως κώδικα (CDK) για τον λογαριασμό της εταιρείας.
- **Μορφή αναφοράς** με σταθερά πεδία που η πλατφόρμα επιβάλλει (ενότητα 5 του εγγράφου σχεδίασης), στην ορολογία του Παραρτήματος II.
- **Το harness αξιολόγησης**: τρέξτε τα δικά σας επισημασμένα alerts, πάρτε την πύλη, το safe close rate, το override rate, ανάλυση ανά σενάριο, πιστότητα, κριθείσα ποιότητα, παλινδρόμηση έναντι της προηγούμενης διαμόρφωσης, και τον κανόνα προώθησης. Αυτό είναι και η δοκιμή αποδοχής στο go-live.
- **Τον βρόχο μάθησης** με τους τέσσερις μηχανισμούς του και τον κανόνα προώθησης.
- **Τεκμηρίωση** για την ομάδα εποπτείας (`08-broker-brief.md`), για τη συζήτηση με τον ρυθμιστή (ενότητες 6-9 της σχεδίασης), και για τη λειτουργία (`07-resume.md`).

Τι παρέχει ο πελάτης: γεγονότα εντολών με καλύτερο bid/ask, συναλλαγές, μητρώο traders, γεγονότα αγοράς, στατιστικά instruments, τα alerts, τις γραπτές διαδικασίες της εταιρείας, πάροχο ταυτότητας OIDC με δύο ομάδες. Η ενσωμάτωση γίνεται στο επίπεδο δεδομένων (πίνακες DynamoDB στο demo· οποιαδήποτε αποθήκη μπορούν να διαβάσουν οι Lambdas των tools).

## 8. Ειλικρινή όρια (πείτε τα πριν τα βρει ο αγοραστής)

- **Συνθετικά δεδομένα.** Το dataset είναι γεννημένο· οι παραπάνω αριθμοί είναι σε αυτό. Το harness είναι φτιαγμένο να τρέξει στα επισημασμένα alerts μιας εταιρείας, και αυτό το run είναι η δοκιμή αποδοχής, όχι αυτοί οι αριθμοί.
- **Ένας τύπος κατάχρησης, μία κατηγορία περιουσιακών στοιχείων, ένας τόπος.** Spoofing και layering σε μετοχές cash. Άλλα σενάρια χρειάζονται δικούς τους διακριτές και κείμενο προτύπου· η αρχιτεκτονική δεν αλλάζει.
- **Μη ντετερμινιστικό μεταξύ runs.** Το ίδιο alert μπορεί να αλλάξει μεταξύ κλεισίματος και κλιμάκωσης σε διαφορετικές μέρες (το alert E το έκανε). Οι επιδείξεις ενός alert δείχνουν συμπεριφορά· μόνο το run του dataset τη μετρά, και ο κανόνας προώθησης έχει κατώφλι ουσιώδους για αυτόν τον λόγο.
- **Τα stop-outs κλιμακώνονται.** Ένας trader που βγαίνει με ζημία μετά από στοίβαξη μεγάλων μονόπλευρων εντολών μοιάζει, σε ένα παράθυρο, με αποτυχημένο spoof· οι απόπειρες είναι αναφερτέες. Το προϊόν τα κλιμακώνει (ασφαλές)· αν το πρότυπο μιας εταιρείας πρέπει να τα κλείνει είναι απόφαση της εταιρείας.
- **Δεδομένα που πρέπει να έχει ο πελάτης.** Ο agent διαβάζει μόνο τους πίνακες της εταιρείας και δεν φτάνει τίποτα έξω από αυτούς (όχι web, όχι εξωτερικό API), που είναι η υπόσχεση ελεγξιμότητας. Χρειάζεται επομένως το feed γεγονότων αγοράς της εταιρείας με χρονοσφραγίδες αγοράς ακρίβειας milliseconds για να δουλέψει η εξήγηση της αντίδρασης σε είδηση· χωρίς αυτό, αυτά τα alerts κλιμακώνονται, δεν κλείνονται.
- **Ρυθμός.** Οι διερευνήσεις ενός αναλυτή τρέχουν δύο τη φορά μέσα στο όριο ρυθμού· το όριο είναι φρένο εκ σχεδιασμού. Εταιρεία με μεγάλη ουρά διαστασιολογεί τα όρια και το Runtime αντίστοιχα.
- **Δεν ισχυριζόμαστε ρυθμιστική έγκριση.** Η σχεδίαση προορίζεται να είναι υπερασπίσιμη· αν μια δεδομένη ΕΑΑ δέχεται αιτιολογήσεις γραμμένες από agent είναι ερώτημα του compliance officer.
- **Οι vendors προσθέτουν δυνατότητες AI διερεύνησης.** Ο ισχυρισμός είναι στενότερος: ένα ελεγχόμενο, ελέγξιμο στρώμα που δουλεύει δίπλα σε οποιονδήποτε detector, για εταιρείες που δεν θα αγοράσουν πλατφόρμα tier-1.

## 9. Οδικός χάρτης, με τη σειρά που θα το ζητούσε πελάτης

1. Κάρφωμα endpoint `demo`· ελληνικό και αγγλικό deck (Φάση 6).
2. Εκτέλεση του harness στα επισημασμένα alerts πιλοτικού πελάτη· το δικό της κείμενο διαδικασιών· αποδοχή = η πύλη.
3. MCP client με επανάληψη είναι μέσα (v12)· επόμενο, A/B test μέσω Gateway με online evaluation config για εταιρείες που θέλουν ζωντανή σύγκριση δύο bundles.
4. Νυχτερινή προ-διερεύνηση της ουράς (γεγονός detector -> Runtime υπό service identity), ώστε οι αναφορές να είναι έτοιμες όταν φτάνει ο αναλυτής. Χρειάζεται δικές του δηλώσεις Policy για το machine principal και αλλάζει το αρχείο από «διερευνήθηκε από τον αναλυτή Χ» σε «προ-διερευνήθηκε από το σύστημα, αποφασίστηκε από τον Χ». Προσφέρεται ως επιλογή, όχι ως προεπιλογή.
5. Δεύτερος τύπος κατάχρησης (wash trades ή marking the close) ως νέο σύνολο διακριτών και παραγράφων προτύπου.
6. Agent reviewer L2 μέσω A2A που αμφισβητεί την αναφορά L1· δημοσίευση στο Agent Registry.
7. Code Interpreter για το γράφημα διαδρομής τιμής στην αναφορά.

## 10. Η ιστορία μίας σελίδας για συζήτηση πωλήσεων

Ο detector σας σηκώνει 150 alerts τον μήνα και τα 130 είναι οι δικοί σας market makers και αλγόριθμοι. Καθένα εξακολουθεί να παίρνει μισή ώρα αναλυτή και γραπτή σημείωση. Αυτό τρέχει το πρώτο πέρασμα του αναλυτή σε 30 δευτερόλεπτα, στον λογαριασμό σας, υπό το γραπτό πρότυπό σας, και δίνει στον αναλυτή σας αναφορά με κάθε αριθμό τεκμηριωμένο, κάθε νόμιμη εξήγηση εγκεκριμένη ή αποκλεισμένη, και μια πρόταση. Δεν μπορεί να καταγράψει τίποτα: η πλατφόρμα δεν του δίνει τέτοιο tool, και η μηχανή κανόνων αρνείται πρόταση που γίνεται πριν διαβαστούν τα τεκμήρια. Σε επισημασμένο σύνολο δοκιμής έκλεισε το 93,5% των ψευδώς θετικών, δεν έκλεισε κανέναν πραγματικό spoofer, και διαφώνησε με το ground truth σε 1 alert στα 15, ενώ οι κανόνες του ίδιου του detector, που κλείνουν περισσότερα, έκλεισαν έξι spoofers. Κάθε διερεύνηση αφήνει το ίχνος που ζητά ο κανονισμός. Όταν το διορθώνετε, η διόρθωση αποθηκεύεται, του δείχνεται την επόμενη φορά, και γίνεται περίπτωση δοκιμής. Όταν το αλλάζουμε, η αλλαγή βγαίνει μόνο αν εξακολουθεί να μην κλείνει πραγματική κατάχρηση στο σύνολο δοκιμής σας.
